# 06｜测试与验收

[返回阅读入口](README.md) · [下一章：CD](07-continuous-delivery.md)

## 1. 输入、产出与重点

输入是明确的代码或制品版本、测试范围、测试数据和环境；产出是可复查的验证证据、缺陷及剩余风险。

测试贯穿开发和交付。单元测试可以在本地和 CI 执行；集成测试可以在 CI 启动临时数据库；完整系统验证可能需要把候选制品部署到集成环境。本文单列这一章，是为了说明环境验证和业务验收怎样连接 CI 与 CD。

## 2. 谁负责

业务开发对实现及基础自动化测试负责。测试人员补充系统场景、组织质量验证并推动风险闭环。产品或业务代表确认业务验收。平台团队提供环境、执行、报告和证据关联能力。

测试团队的确认不替代业务开发的质量责任；平台上的“通过”也需要能追溯到具体测试范围。

## 3. 各类测试分别验证什么

| 类型 | 本案例的检查内容 | 适合位置 | 主要局限 |
|---|---|---|---|
| 单元测试 | 参数限制、状态判断、用户条件构造 | 本地／CI | 常隔离了真实依赖 |
| 数据访问集成测试 | 真实数据库的 SQL、排序、分页、索引行为 | CI 临时依赖／集成环境 | 数据规模与生产可能不同 |
| API 测试 | 身份、状态码、响应结构、越权、空结果 | 本地服务／部署后 | 不一定覆盖前端用户路径 |
| 契约测试 | 消费方与提供方对字段和交互的约定 | CI／跨服务验证 | 需要参与方维护契约 |
| 端到端测试 | 用户进入页面、筛选并查看订单 | 测试／预发环境 | 成本和脆弱性较高 |
| 性能与容量验证 | 延迟、吞吐、慢 SQL、资源饱和 | 受控压测环境 | 必须说明数据量与负载模型 |
| 安全验证 | 用户隔离、注入、敏感信息、依赖风险 | CI＋专项环境 | 扫描器不能覆盖全部业务风险 |
| 业务验收 | 结果是否满足需求与体验 | 测试／预发环境 | 不覆盖所有技术正确性 |
| 上线冒烟 | 生产路由、权限、依赖和核心查询能否工作 | 发布过程中 | 场景少，不能替代完整测试 |

测试层次是选择验证手段的思路，不意味着每个项目都要配置相同数量的测试或独立平台。

## 4. 环境和数据常常比测试脚本更难

### 环境可识别

需要记录运行中的制品摘要、部署配置、依赖版本、数据库结构和测试时间。出现问题时，才能知道测试的是哪套组合。

共享环境上被另一组发布覆盖，是一种环境冲突。可以通过预约、隔离命名空间或临时环境缓解，但隔离同时还要考虑账号、数据、队列和外部服务。

### 数据可构造

本案例至少准备两个不同用户、各类订单状态、空结果和分页边界。大数据量验证还要设计合理分布，不能只插几条记录就宣称性能满足生产目标。

测试数据使用合成数据或经过批准的脱敏流程。练习中用合成用户与订单即可。

### 依赖可控制

Mock 便于构造失败，但与真实服务行为可能有偏差。对关键依赖应结合契约测试、真实集成和超时场景验证。

使用 [Testcontainers](https://testcontainers.com/) 管理测试中的容器依赖时，还要确认执行器具备所需容器运行能力和资源；它并不自动解决所有跨服务环境问题。

## 5. 验收结果应绑定什么

建议保存：

```text
TestRun
  - 测试计划 / 用例版本
  - 代码提交或制品完整摘要
  - 环境与配置快照标识
  - 测试数据版本 / 负载参数
  - 执行人或执行器
  - 开始与结束时间
  - 结果、报告、缺陷和例外
```

同一制品换了数据库结构、关键配置或运行架构，旧测试证据是否仍然足够，需要规则判断。只保留“本周已通过测试”的文字，无法约束实际发布对象。

## 6. 平台后端的典型开发任务

- 为 MR 创建临时环境，配置到期回收和异常回收。
- 调度测试，保存报告，并和发布单关联。
- 管理测试数据初始化、隔离和清理流程。
- 把门禁结果回写代码平台或 CD。
- 区分应用失败、测试框架失败、环境不可用和结果未知。
- 统计不稳定测试，保留首次失败证据。

删除临时环境前，要验证所属项目与运行状态；环境回收失败也需要可追踪的任务记录。

## 7. 技术栈与代表性开源项目

| 项目 | 适用位置 | 应先学什么 |
|---|---|---|
| [Testcontainers](https://testcontainers.com/) | 代码测试中的临时数据库等依赖 | 生命周期、就绪判断、数据准备 |
| [Pact](https://docs.pact.io/) | 消费方与提供方的契约测试 | 契约表达、验证和版本兼容 |
| [k6](https://grafana.com/docs/k6/latest/) | 负载生成、指标和性能阈值 | 负载模型、检查与阈值 |
| [Playwright](https://playwright.dev/docs/intro) | 浏览器端到端测试 | 用户路径、断言、测试隔离 |

对平台后端岗位，先掌握 API 和依赖集成测试，再了解跨服务和端到端验证如何接入，不要求先成为所有测试工具的专家。

## 8. 核心技能与案例验收

| 深度 | 本章应掌握 |
|---|---|
| 理解 | 不同测试覆盖的风险，测试结果的适用范围 |
| 使用 | 写自己的语言测试、构造依赖和数据、分析失败报告、做受控压测 |
| 开发平台 | 环境生命周期、测试调度、报告规范、证据绑定和门禁 |

本案例要留下权限、分页、状态过滤和数据库集成测试；部署后验证实际路由；用可复现负载检查延迟与数据库瓶颈。测试通过后明确哪些风险仍未覆盖。

自测：CI 单元测试全绿，生产接口返回了别人的订单，测试设计和需求验收可能缺少哪些内容？
