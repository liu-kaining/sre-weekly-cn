# 服务端开发转 DevOps／研发效能平台：从需求到生产运行

面向有约 3 年服务端开发经验、准备应聘研发效能平台后端研发岗位的读者。

推荐使用[单页 HTML 完整版](index.html)阅读：包含完整正文、流程图、目录、全文搜索和阅读进度，单独保存这一份 HTML 即可离线打开。

这套指南用一个功能的交付过程回答三个问题：功能经过哪些阶段；每个阶段做什么、谁负责、依赖什么技术；平台工程师需要把哪些事情做成可复用的能力。

资料核对日期：2026-10-16。岗位分工是本文的教学模型，工具定位以各章官方参考资料为依据。实际公司的流程、权限和产品版本可能不同；阅读 JD 和面试交流时需要对应确认。

## 先抓住岗位的工作对象

过去写业务服务，主要面对订单、账户、支付等业务对象。开发研发效能平台，主要面对应用、代码仓库、构建任务、制品、环境、发布单和运行事件。

你已有的接口设计、数据库、异步任务、权限、并发控制和故障排查经验都能迁移。需要补齐的是软件交付过程，以及这些对象之间的状态、约束和失败处理。

本文会分别讨论：

- 业务开发怎样借助平台交付功能。
- 平台后端怎样实现流水线、发布编排、环境管理和运行反馈。
- 平台依赖的 Jenkins、Kubernetes 等系统各自负责什么。

## 建议怎样读

第一次先读 01 和 11，建立流程与岗位的整体认识。随后按 04 → 05 → 06 → 07 → 08 → 09 理解交付主链。最后用 12 制定学习安排，用 13 完成一次练习。

阅读一章后，试着不看原文回答：

1. 这一阶段接收什么，产出什么？
2. 谁对结果负责，平台提供什么支持？
3. 正常路径怎样走，失败后怎样判断和处理？
4. 如果由我写平台后端，接口、数据和异步任务怎样设计？

能用自己的话讲清楚这些，比记住工具名称更接近岗位要求。

## 全文共用案例

给已有的 `order-service` 新增“查询当前用户已支付订单”的接口：

```http
GET /orders?status=paid&limit=20
```

请求的用户身份来自认证上下文。接口需要做权限校验、访问订单数据库，并在生产流量下满足团队约定的性能与可靠性目标。后续各章跟踪同一个功能的代码、测试结果、镜像、部署记录和运行反馈。

文中的性能数值、时间、标识符、状态机和平台表结构都是教学示例。实操章提供任务、配置思路和验收方法，完成练习时使用自己熟悉的语言另建业务项目。

## 技能深度的约定

| 层次 | 达成标准 | 示例 |
|---|---|---|
| 理解 | 能解释目的、边界和常见失败 | 解释为什么部署完成还需要业务验证 |
| 使用 | 能独立配置、执行、检查结果并排障 | 写一条 CI，定位失败任务，检查部署事件 |
| 开发平台 | 能设计可复用、可审计、能恢复的能力 | 为重复发布请求做幂等，处理超时与状态对账 |

初期目标是掌握主链的“理解＋使用”，再对流水线或发布平台中的一个模块达到“开发平台”。无需在应聘前精通所有开源项目。

## 工具选择原则

各章列出的是代表性项目，方便认识不同能力的实现方式。相邻阶段可能由同一个平台覆盖，也可能由几个系统组合完成。

开源软件、商业增强版本和托管服务会明确区分。实操优先选一套能完成闭环的组合，产品的功能与版本边界通过官方资料确认，资料入口统一收录在第 14 章。
